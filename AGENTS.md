# Project instructions

## Public repository

This repository is public. Keep tracked files free of personal details: no real
domains, hostnames, IP addresses, local file paths, usernames, or secrets. Use
reserved examples (`example.com`, `203.0.113.0/24`, `~/vitals`) and keep
deployment instructions generic.

## Commit and push after every change

After changing this repository, always commit the change and push it to the
configured remote(s) without waiting for a separate request.

- Check the change first; do not commit a broken tree.
- Stage only the intended files. Never stage `.env` or other secrets.
- Follow the global commit-attribution rules for the author, committer, and the
  user's co-author trailer.
- Push to the configured remote(s) and branch. If a push fails, report the
  error and the local commit; do not force-push.
